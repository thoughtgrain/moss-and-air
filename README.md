# The Bryo site

This folder is Bryo's website: a landing page and a short documentation page, in plain HTML, CSS and JavaScript.
No framework, no build step, no `node_modules`. GitHub Pages serves it from the `gh-pages` branch.

## What's in here

```
site/
├── index.html        the landing page: the instrument, the chain, sources, specs, getting it, thanks to Felucca
├── docs.html         the short guide (install, the panel, recording, saving, reference, building, credits)
├── css/style.css     every style, with the colour and type tokens at the top
├── js/main.js        the menu, the hero's screens, the chain tabs, the docs' contents and copy buttons
├── fonts/            Bryo PX5, the firmware's screen face, regular and bold (generated)
├── img/
│   ├── wordmark.svg  BRYO in PX5, as the boot screen spells it (generated)
│   ├── favicon.svg   a B in PX5 (generated)
│   ├── panel.svg     the FM-1 panel as Bryo uses it now (generated)
│   ├── icons.svg     the menu, close and GitHub icons as <symbol>s
│   └── *.png         real Bryo screens, copied from bryo/docs/manual/img
├── tools/
│   ├── gen_px_webfont.py   the fonts, the wordmark and the favicon, from the firmware's PX5 table
│   └── gen_panel.py        panel.svg, from the same table, the screen's colours and a real render
└── .nojekyll         tells Pages to serve the files as they are
```

## The look, and why

I took the cues from Elektron's product pages: near-black, hairline rules, a sticky strip with the product's name
and one outlined button, big tight headings with a pixel-type `/ 01` above each section. It fits because the FM-1's
screen *is* pixel art, and the pictures here are the real thing: rendered by the same C code that runs on the
device (`tests/bryo_host.c`), on its 2×2 px dot grid. `image-rendering: pixelated` keeps them crisp when they scale.

Every graphic comes from the current firmware, not from Felucca and not from a lookalike. That was the point of a
second pass: the first version used Silkscreen as a stand-in for the screen's type, a generic tilted bezel round the
screen, a boxed-B logo and the manual's older panel drawing (Helvetica, ENV still labelled "M2"). Now:

- **The type is the firmware's.** `tools/gen_px_webfont.py` reads `PX5`, the 5×7 face in
  `bryo/tools/gen_px_font.py` (the same table `ui_pxfont.h` is built from), and writes it as a web font: a dot is a
  dot, 6 dots a character like `px_text()`, and a bold cut with each dot doubled to the right, 7 a character, like
  the screens' titles. Lower case folds to capitals as `px_glyph()` does. A character PX5 doesn't draw isn't in the
  font, so I keep pixel text to what it has (no `·`, no `ü`, no `&`), or the browser falls back to a plain mono.
- **The wordmark is the boot screen's.** BRYO in PX5, generated by the same script.
- **The colours are the firmware's,** value for value from `firmware/src/ui_px.c`: black, white, and Okabe and Ito's
  colour-blind-safe accents (sky blue `#56B4E9` a page, reddish purple `#CC79A7` modulation, orange `#E69F00`
  sound, vermillion `#D55E00` recording, yellow `#F0E442` something to know).
- **The panel is drawn from the current controls.** `tools/gen_panel.py` letters it in PX5, edges each pad in the
  colour the screen gives its pages, puts a real TAPE render in the screen, and dims the two black keys
  `docs/controls.tsv` still marks as planned (PIT, GLO).
- **The screens are the real renders,** shown flat at a whole multiple of their size, with no bezel.

### Wireframe, and mono all the way down

The third pass took out every filled surface and the last proportional font. The reasoning: the screen draws
everything in 1-dot strokes and dotted guides, and a site about it reads more like it when it's drawn the same way.

- **No fills, no glows.** Buttons, tabs, cards, callouts, tables and code blocks are 1 px wires on black. The main
  button is told apart by a doubled border and a `>`; the selected chain tab by an inner frame and a blue bar
  under it (a page's colour, as on the screen). Hover and focus change the wire's colour, not a background.
- **Guides are dashed**: figure captions, inline code, the keybed and the not-yet-assigned keys on the panel.
- **A drafting grid** of 1 px lines every 48 px sits behind the hero, fading out as you scroll.
- **Registration ticks**, an L of white at each corner, mark the things you look at: the screens, the panel, the
  sponsor card. They're one pseudo-element of eight 1 px gradients each, so there's no extra markup, and they hide
  in Windows' forced-colours mode where they'd just be noise.
- **The panel drawing is a wireframe too:** outlines only, the dashed keybed, PIT and GLO dashed and dim. It keeps a
  black ground so it still reads when it's opened on its own on a white page.

Type is split by job, and both faces are fixed-width:

- **Bryo PX5** (the firmware's boxy screen face) for labels, buttons, numbers and nav. Short strings only.
- **IBM Plex Mono** for everything you read, headings included, and for code. It's a mono that was drawn for
  reading, with real italics and a 600 weight that holds up at heading size. Headings get tight negative tracking
  (−0.045 em) so the fixed-width letters don't drift apart when they're big; body text stays at its natural spacing
  and a 64-character measure, since mono runs wider than a proportional face.

When the firmware's look changes, regenerate from the repository root:

```sh
python3 site/tools/gen_px_webfont.py     # PX5 changed: fonts, wordmark, favicon
python3 site/tools/gen_panel.py          # a control's job or a colour changed: the panel
cp bryo/docs/manual/img/{arp,arp_add,arp_drum,arp_fade,arp_res,boot,color,crash,drum,follow_live,grain,grain_frozen,grain_playing,mixer,mixer_morph,mixer_scenes,mod1,poly_loop,poly_twin,projects_scenes,reso_live,ripple2,ripple_comb,ripple_flow,space,space2,space4,space_live,space_long,synth_env2,synth_fm,synth_shape,synth_wt,tape,tape_frze,tape_playing}.png site/img/
```

Both scripts need fontTools only for the fonts (`pip3 install fonttools`); the panel needs nothing beyond Python.

Colour isn't decoration. It follows Bryo's own screen rule: white on black, and colour only says where you are or
what's alive. Blue is a page, purple is modulation, orange is sound, red is recording, yellow is something to know.
The tokens live at the top of `css/style.css`.

## The walkthrough ("Watch your hands")

The homepage's section 02 plays the FM-1 for you. I wanted people to see the instrument's whole idea (hold a pad,
turn a knob, no menus) before reading about it, so the panel drawing is the stage:

- `js/main.js` (`initTour`) fetches `img/panel.svg` and puts it inline. `tools/gen_panel.py` gives every control a
  group, `<g id="ctl-NAME">`, with its outline as `rect.hit` and a knob's pointer as `rect.ptr`, so CSS can light
  them. The names are listed at the top of the generator.
- Each routine (Pages, Tape, Grains, Scenes, Arp) is a list of steps in `TOUR`. A step can **press** controls (a short
  orange flash, one after another), **hold** them (lit with a faint fill for the whole step) and **turn** knobs (the
  pointer swings to an angle), then it swaps the screen: the big one beside the panel and the panel's own.
- Every screen is a real render from the manual, picked so it matches the step. Where no render exists for a moment
  (GRAIN switched on but stopped, say), I ordered the steps so the picture is always true.
- If the fetch fails, the plain `<img>` panel stays and the steps and screen still work.

It plays by itself only while it's on screen and the tab is visible, never with `prefers-reduced-motion`, and stops
once you use Prev, Next or a step (then each step is announced in a polite live region). The panel itself is
`aria-hidden`: the numbered steps say in words what the hands are doing.

## Accessibility

Since this is a page about an instrument with no menus, I wanted the site itself to be just as direct to use, with
any input:

- A skip link, landmarks, one `h1` per page and headings in order.
- The menu is a native `<dialog>` opened with `showModal()`, so focus is trapped and Escape closes it without
  extra code. Closing it returns focus to the button that opened it.
- The chain is a WAI-ARIA tabs widget: arrow keys, Home and End move between stages, and only the selected tab is
  in the tab order.
- The hero's screens change on their own, so there's a Pause button (WCAG 2.2.2). With `prefers-reduced-motion`
  they start paused. It's one `<img>` whose source changes, with every screen loaded first: the first version
  stacked lazily-loaded images under a 3D tilt, and on iPhone the screens after the first didn't show.
- Wide tables scroll inside their own focusable region, never the page, so nothing scrolls sideways at 320 px.
- Text contrast is at least 6.6:1 (the faintest grey) and 10.6:1 for body copy. The firmware's own dim ink
  (`#737373`, 4.5:1) is only used in the panel drawing, never for page text. Focus rings are a 2 px yellow
  outline. Colour swatches in the docs always sit next to the colour's name.
- Copy buttons announce "Copied" through a `role="status"` region, and fall back to selecting the text when the
  clipboard isn't available.

## Working on it locally

Any static server works. From the repository root:

```sh
python3 -m http.server 8000 --directory site
# open http://localhost:8000
```

Open it through a server, not `file://`: the icons are an external SVG sprite (`<use href="img/icons.svg#logo">`),
and browsers block that from `file://`.

If a manual screen changes (`tools/gen_manual_shots.py` regenerates them), copy the new PNG over the one in
`site/img/`. I copy them rather than pointing at `bryo/docs/manual/img/` because Pages only serves this folder.

## Deploying

`.github/workflows/pages.yml` runs on every push to the default branch that touches `site/` (or by hand from the Actions tab).
It first checks that every local `src` and `href` in the pages points at a real file, then pushes the contents of
`site/` to the `gh-pages` branch as a single fresh commit. Rebuilding the branch from scratch each time keeps it
small, since it never carries the source's history.

One setting is needed once, in the repository on GitHub: **Settings → Pages → Build and deployment → Source:
Deploy from a branch**, branch **gh-pages**, folder **/ (root)**. The site then lives at
<https://thoughtgrain.github.io/moss-and-air/>.

All the links back into the repository use `blob/HEAD/...`, which GitHub resolves to the default branch, so they
keep working whatever that branch is called.
